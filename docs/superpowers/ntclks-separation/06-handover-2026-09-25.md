## 3. 阶段 5b 提交（99fb5c6）做了什么——接手者必读

- `git rm` 旧内核树（kernel/ drivers/ boot/loader/ include/uapi include/linux，-84591 行），
  `kernel/ntclks` gitlink 钉 `5cc9621`；`include/leonos` 逐文件处置：`boot_handoff.h/
  elf_abi.h/utf8_stream.h` 删除（内核仓持有）、`driver.h` 裁掉模块 API（留 runtime+转发）、
  `layout.h/psf_font.h/text.h/fb.h` 与字体数据留用户态（内核仓自有副本，设计 §5.7）。
- 测试/工具路径迁移：`tools/tests/*`（白盒 ~120 处 include）、`test_uapi/test_gpu`、
  `analyze_boot_log.py`、vscode 工具、现行文档。映射：`kernel/ntclks/…`→
  `kernel/ntclks/kernel/ntclks/…`、`drivers/…`→`kernel/ntclks/drivers/…`、
  `boot/loader/…`→`kernel/ntclks/boot/loader/…`、`include/uapi/…`→`kernel/ntclks/include/uapi/…`。
- 新增 `tools/build/ntclks-release-guard.sh`（rpr-pages/release 拒绝 dirty 或 SHA 不配对
  子仓；`all` 不设限——dev 可 dirty）与 `tests/build/test-submodule-contract.sh`
  （缺失子仓报错、dirty dev 可构建、发布拒绝、gitlink/子仓 HEAD 一致）。
- CI 工作流加递归 submodule checkout。
- **已验证**：gitlink/`.gitmodules`/子仓 HEAD 三方一致（`git ls-files -s` 160000@5cc9621）、
  `make -n kernel` 解析通过。**未验证**：完整 `make all`、`make test` 全套、
  全新递归 clone 构建、负例/VT 回归——迁移动了 148 个文件，**预期会有测试 fallout**。

## 4. 换机注意（环境差异）

- 旧机上 `cache/`、`buildsystem/` 是指向主检出缓存的符号链接（不入库）；新机直接
  `make fetch` 重建下载缓存（约 200MB+）。`make doctor` 会列出缺什么（OVMF=`edk2-ovmf`、
  tesseract、qemu-system-x86_64、mke2fs/mkfs.fat/mtools/xorriso/grub-mkstandalone 等）。
- 旧机 `/home/leon/build/ntclks-sep/` 下的全部构建输出/日志/截图**不迁移**（机器本地）。
  本文档即证据汇总；需要实证时按 §5 清单重跑。
- QEMU 测试需 KVM（`/dev/kvm`）与 `/usr/share/edk2/x64/OVMF*.4m.fd`；QMP socket 用 `/tmp`。
- 安装器测试用 `--install-timeout 3600`（默认 1200s 会截断健康安装，本机约 25 分钟；00§4）。

```sh

git clone --recurse-submodules . /tmp/p5-fresh && (cd /tmp/p5-fresh && git submodule update --init --recursive && make fetch && make O=/tmp/p5-f2 all && make O=/tmp/p5-f2 test)   # ④ 全新递归 clone
git clone . /tmp/p5-nosub && (cd /tmp/p5-nosub && make O=/tmp/p5-n3 kernel)   # ⑤ 无子仓→明确报错
sh tests/build/test-submodule-contract.sh         # ⑥ 契约测试（含 dirty 发布拒绝）
```

`test_uapi` 三路径、`test_gpu` 编译源路径、`analyze_boot_log` 映射表、
`test_motd.c` 的 include、mk 中未改净的字面路径。**修测试而非放松断言。**
